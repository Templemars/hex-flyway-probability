## Autumn endpoint-domain fix

- Autumn migration direction must be treated explicitly as **southward** in the prototype endpoint rule, so autumn cases should route from the northern benchmark end toward the southern benchmark end rather than reusing the spring northward ordering.
- A direct graph-domain check against the current ERA5-supported H3 routing mask showed that this is **not** a general autumn failure:
  - `svalbard_autumn_afaf` has valid start and end cells in the graph
  - `svalbard_autumn_amam` has valid start and end cells in the graph
  - `netherlands_autumn` fails specifically because its northern benchmark endpoint maps to H3 cell `831951fffffffff`, which is **not** in the current routing graph / wind-supported domain
- Explicit fix rule for `netherlands_autumn`:
  - keep the benchmark-derived autumn direction as **north to south**
  - if a benchmark endpoint maps to an H3 cell outside the routing graph, replace it with the **nearest valid in-domain H3 cell** to that benchmark coordinate
  - record the substituted cell and the reason for substitution explicitly in the endpoint output / notes
- Treat this as a prototype domain-alignment correction, not as a hidden silent fallback.

## Autumn debugging and sweep-core refactor work

- We attempted the first autumn bounded runs under the new case-based workflow and discovered that autumn execution problems were initially mixed together: execution-monitoring problems, endpoint-direction issues, and potential sweep-core inefficiency.
- We confirmed that the autumn benchmark summaries are ordered consistently with **southward autumn migration** for the relevant cases, so autumn should start from the northern benchmark end and move southward.
- We patched the shared endpoint helper so it actually respects `first_row_of_...` versus `last_row_of_...` rules rather than always taking first row as start and last row as end.
- We updated the autumn case definitions accordingly:
  - `netherlands_autumn`
  - `svalbard_autumn_afaf`
  - `svalbard_autumn_amam`
  all now use north-to-south endpoint ordering.
- We then checked the autumn endpoints directly against the current ERA5-supported H3 routing graph:
  - `svalbard_autumn_afaf` endpoints are graph-valid
  - `svalbard_autumn_amam` endpoints are graph-valid
  - `netherlands_autumn` northern endpoint falls outside the supported routing graph
- We computed and documented the explicit Netherlands autumn endpoint substitution:
  - original northern benchmark coordinate near lon **-3.81**, lat **53.59**
  - nearest valid in-domain H3 substitute: **`831953fffffffff`**
  - this substitution is now recorded explicitly in the case config and endpoint metadata rather than applied silently
- We improved execution transparency during the day:
  - long sweep scripts now print progress more clearly
  - the shared heavy sweep script now prints **every behavior**, not just every 10 behaviors
  - this was necessary because sparse progress logging made it too hard to tell whether long runs were alive, slow, or dead
- We also identified a core computational weakness in the repeated full bounded sweep implementation:
  - the old shared sweep loop copied the full edge dataframe for every behavior
  - recomputed weighted costs in that copy
  - rebuilt a fresh `networkx` graph for every behavior
  - then ran Dijkstra
  - this was transparent but computationally wasteful and likely part of the reason autumn debugging became so unstable on the current laptop
- We partially refactored that sweep core:
  - the shared sweep now prebuilds a reusable base graph once
  - stores the component cost arrays once
  - updates only edge weights per behavior
  - and reuses the graph structure instead of rebuilding it from scratch on every behavior
- Validation result from the refactored sweep is encouraging but incomplete:
  - before the refactor, autumn debug runs appeared to die very early, around behaviors **9 to 10**
  - after the refactor, the `svalbard_autumn_afaf` validation run reached at least **behavior 15** with clean per-behavior output
  - however, it still did not complete, so the refactor appears to have helped but not fully solved the deeper run-failure problem
- Current interpretation at the end of the day:
  - autumn direction handling is now conceptually correct
  - Netherlands autumn endpoint-domain mismatch has been identified and explicitly documented
  - the heavy sweep loop was indeed too inefficient and has been partially improved
  - but the bounded autumn runs still show unresolved deeper instability / termination before completion
- This means the next session should begin from the updated notes and code state, not by repeating the same blind autumn runs.
